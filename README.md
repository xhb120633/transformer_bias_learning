# Transformer Mechanism Calibration

## Implementation Specification for a Synthetic Two-Mechanism Benchmark

**Status:** Phase 1 design, implementation-ready  
**Date:** 2026-08-26  
**Primary target:** A working pilot that tests whether a transformer’s learned causal reliance tracks the data-generating mechanism  
**Initial model scope:** Small decoder-only causal transformer trained from random initialization  
**Intended user of this document:** Codex or another coding agent building the repository and running the first experiments

---

## 1. Project objective

Build a controlled synthetic benchmark for the following question:

> When behavioral data are generated by multiple causal mechanisms, does a high-performing transformer learn and represent those mechanisms in proportion to their true contribution, or does its architecture and training objective systematically favor one mechanism?

The initial task contains two genuine data-generating effects:

1. **Reward dependence:** choices depend on learned option values derived from reward history.
2. **Choice dependence:** choices depend directly on the preceding choice through a choice kernel.

The relative strength of these mechanisms is known and manipulated by construction. A causal transformer is trained only to predict the next choice from the preceding behavioral sequence. We then measure whether its actual predictive mechanism changes with the true mixture.

The central result is a **mechanistic calibration curve**, not a single accuracy number:

\[
\text{true choice-kernel reliance}
\quad \longrightarrow \quad
\text{transformer choice-history reliance}.
\]

If the model is mechanistically calibrated, the curve should approximately follow the identity line. A systematic slope error, threshold, saturation, or persistent preference for one input channel constitutes evidence that predictive fit does not transparently recover the data-generating mechanism.

---

## 2. Core conceptual distinction

The codebase must keep three quantities separate throughout:

### 2.1 Generator-level mechanism: \(\lambda_G\)

The relative causal contribution of reward and choice dependence in the synthetic data generator. Because coefficients can have different scales and act through a nonlinear choice function, this must be defined through matched interventions rather than raw coefficient magnitude.

### 2.2 Model-level mechanism: \(\lambda_M\)

The trained transformer’s causal reliance on reward history versus choice history, measured by controlled counterfactual changes to its inputs.

### 2.3 Analysis-level estimate: \(\lambda_A\)

The conclusion suggested by conventional model-analysis tools, initially:

- input-channel ablation or permutation importance;
- hidden-state probes for reward value and choice kernel;
- optionally, later activation patching.

Two distinct failures are possible:

\[
\lambda_M \neq \lambda_G
\quad \text{(learning or mechanistic-calibration failure)},
\]

and

\[
\lambda_A \neq \lambda_M
\quad \text{(analysis failure)}.
\]

These must never be conflated. A correct analysis can reveal that the model learned the “wrong” mixture, and a poorly calibrated analysis can misdescribe a model that learned the mixture correctly.

---

## 3. Locked Phase 1 scope

### 3.1 Included

- A two-option sequential choice task.
- Synthetic subjects generated from a known mixture of reward learning and a choice kernel.
- Full-feedback rewards in the primary benchmark, so reward evidence can be manipulated independently of choice history.
- A small causal transformer trained from scratch with supervised next-choice cross-entropy.
- Multiple ground-truth mixture conditions.
- Multiple random generator and training seeds.
- Predictive evaluation, counterfactual reliance measurement, input ablations, and hidden-state probes.
- Reproducible configs, tests, checkpoints, metrics, and paper-ready plots.

### 3.2 Explicitly excluded from Phase 1

- Pretrained language models or instruction-tuned models.
- Natural-language prompting.
- Centaur replication.
- Claims about human cognitive mechanisms.
- Large-scale circuit discovery.
- Sparse autoencoders.
- A claim that decodability establishes computational use.
- Partial-feedback bandits until the clean benchmark works.

These are extensions, not requirements for the pilot.

---

## 4. Why the primary benchmark uses full feedback

In a standard partial-feedback bandit, the observed reward is inseparable from the selected action: removing action history also removes the information required to identify which option received a reward. That makes reward and choice channels difficult to ablate or intervene on independently.

For Phase 1, each trial therefore reveals the outcomes of both options after the choice. The reward process is exogenous to the subject’s action, while the subject’s next choice may still depend on:

- the learned difference between the two option values; and
- the identity of the previous choice.

This design is deliberately simplified. Its purpose is to establish whether mechanistic calibration fails even under unusually favorable identification conditions. A partial-feedback replication becomes more meaningful after this clean case is understood.

## 5. Synthetic data-generating process

### 5.1 Session structure

Each synthetic session contains \(T\) trials and two options, indexed by \(a \in \{0,1\}\).

Recommended pilot defaults:

| Parameter | Default |
|---|---:|
| Trials per session, \(T\) | 64 |
| Training sessions per condition | 10,000 |
| Validation sessions per condition | 2,000 |
| Test sessions per condition | 2,000 |
| Options | 2 |
| Reward outcomes | Bernoulli, full feedback |
| Reward probability levels | 0.25 and 0.75 |
| Reversal hazard | 0.05 per trial |
| Learning rate, \(\alpha\) | 0.25 |
| Choice bias | 0 |

The active high-reward option switches according to a Markov reversal process. On trial \(t\), both outcomes are sampled:

\[
r_t(a) \sim \operatorname{Bernoulli}(p_t(a)),
\]

where one option has probability 0.75 and the other 0.25. The high-reward identity reverses with the configured hazard.

### 5.2 Reward-learning state

Initialize:

\[
Q_0(0)=Q_0(1)=0.5.
\]

Because the task supplies full feedback, update both values after trial \(t\):

\[
Q_{t+1}(a)
=
Q_t(a)+\alpha\left[r_t(a)-Q_t(a)\right].
\]

The reward signal used to generate choice \(a_t\) is:

\[
\Delta Q_t = Q_t(1)-Q_t(0).
\]

### 5.3 Choice-kernel state

For the initial benchmark, use a one-step choice kernel:

\[
K_t =
\begin{cases}
+1, & a_{t-1}=1,\\
-1, & a_{t-1}=0,\\
0, & t=0.
\end{cases}
\]

This makes the causal manipulation exact and interpretable. A decaying choice trace is a Phase 2 extension:

\[
K_{t+1}(a)
=
(1-\rho)K_t(a)+\rho\,\mathbb{1}[a=a_t].
\]

Do not implement the decaying version until the one-step benchmark passes.

### 5.4 Standardized signals

Estimate \(\mu_Q\) and \(\sigma_Q\) once from a large reward-only calibration population generated with the same environment and \(\alpha\). Because rewards are observed for both arms, the distribution of \(Q\) does not depend on the subject’s actions or mixture condition.

Define:

\[
z^Q_t = \frac{\Delta Q_t-\mu_Q}{\sigma_Q},
\qquad
z^K_t = K_t.
\]

Save the calibration statistics in the dataset metadata. Never recompute them separately on train, validation, and test sets.

### 5.5 Mixture parameterization

Use an angular parameterization that keeps the coefficient norm constant:

\[
\eta_t
=
s\left(\cos\theta\,z^Q_t + \sin\theta\,z^K_t\right),
\]

\[
P(a_t=1)=\sigma(\eta_t),
\]

where \(s\) controls overall choice determinism and \(\theta\in[0,\pi/2]\) controls the nominal mixture.

Recommended defaults:

- \(s=1.5\)
- pilot angles: \(0, \pi/4, \pi/2\)
- full sweep: \(0, \pi/8, \pi/4, 3\pi/8, \pi/2\)

The angular parameter is only the **nominal** mixture. The realized ground-truth reliance \(\lambda_G\) must still be measured using the same interventional estimand used for the transformer.

### 5.6 Trial order

For each trial \(t\):

1. Compute \(Q_t\), \(z^Q_t\), and \(K_t\) from prior trials.
2. Sample choice \(a_t\) from the logistic policy.
3. Sample full-feedback rewards \(r_t(0),r_t(1)\).
4. Update both \(Q\) values.
5. Store observable variables and generator latents.

No reward from trial \(t\) may be available when predicting choice \(a_t\).

## 6. Dataset schema and splits

### 6.1 Observable arrays

Each saved session should contain arrays of shape `[T]` or `[T, 2]`:

- `action`: integer in `{0, 1}`.
- `reward`: binary float array `[T, 2]`.
- `high_reward_option`: integer in `{0, 1}`; environment metadata, not model input.

The model loader constructs aligned inputs:

- At position `t=0`: BOS action and zero/BOS reward vector.
- At position `t>0`: `action[t-1]` and `reward[t-1, :]`.
- Target at position `t`: `action[t]`.

### 6.2 Latent evaluation arrays

Save these for evaluation but never expose them to the transformer:

- `q_value[T, 2]`
- `delta_q[T]`
- `z_q[T]`
- `choice_kernel[T]`
- `generator_logit[T]`
- `generator_probability[T]`
- `theta`
- `scale_s`
- `alpha`
- reward environment parameters
- generator seed
- session ID

### 6.3 Storage format

Use compressed NumPy `.npz` shards plus a JSON metadata file for Phase 1. The loader must support memory-mapped or shard-wise loading so the full dataset does not need to reside in RAM.

Each dataset directory must contain:

```text
metadata.json
train_000.npz
train_001.npz
...
val_000.npz
test_000.npz
```

### 6.4 Split rules

- Generate train, validation, and test sessions with disjoint seeds.
- Use independent environment trajectories in every split.
- Never split trials from one session across datasets.
- Store a hash of session IDs in metadata and test that splits are disjoint.
- Fit standardization statistics only on the dedicated calibration population, never on test data.

### 6.5 Generalization sets

After the in-distribution pipeline works, create two held-out sets:

1. **Reversal OOD:** reversal hazards not seen in training, for example 0.01 and 0.15.
2. **Conflict-enriched:** trials or sessions selected to increase disagreement between \(z^Q_t\) and \(z^K_t\).

These are secondary. They must not block the first pilot.

## 7. Transformer model

### 7.1 Model type

A decoder-only causal transformer trained from random initialization. This is structured sequence modeling with a transformer, not language-model fine-tuning.

### 7.2 Input representation

At prediction position \(t\), construct:

\[
x_t
=
E_A(a_{t-1})
+
E_R(r_{t-1}(0),r_{t-1}(1))
+
E_P(t),
\]

where:

- `E_A` is an action embedding with categories `{option_0, option_1, BOS}`;
- `E_R` is a small linear layer or MLP from the two reward values to `d_model`;
- `E_P` is a learned positional embedding;
- the first position uses BOS action and a zero reward vector.

Keep the action and reward embedding contributions separate in code before summation. The forward method must optionally return:

- action-channel embedding;
- reward-channel embedding;
- residual stream after each layer;
- final choice logits.

This is required for later ablation and probing.

### 7.3 Default architecture

| Hyperparameter | Default |
|---|---:|
| Layers | 4 |
| `d_model` | 128 |
| Attention heads | 4 |
| Feed-forward width | 512 |
| Dropout | 0.1 |
| Maximum sequence length | 64 |
| Output classes | 2 |
| Positional embeddings | Learned |
| Normalization | Pre-LayerNorm |

Use PyTorch’s transformer components or a small transparent custom implementation. Prefer clarity and hookability over framework abstraction.

### 7.4 Causal alignment

The output logit at position \(t\) predicts `action[t]` and may depend only on:

```text
action[0:t-1], reward[0:t-1]
```

It must not depend on `reward[t]`, `action[t]`, or any later data. Add an explicit no-future-leakage test.

### 7.5 Training objective

Use cross-entropy across all valid positions:

\[
\mathcal{L}
=
-\sum_{n,t}\log P_\phi(a_{n,t}\mid a_{n,<t},r_{n,<t}).
\]

Default optimization:

| Setting | Default |
|---|---:|
| Optimizer | AdamW |
| Learning rate | `3e-4` |
| Weight decay | `1e-2` |
| Batch size | 128 sessions |
| Gradient clipping | 1.0 |
| Warmup | 500 steps |
| Scheduler | cosine decay |
| Max epochs | 50 |
| Early stopping | validation NLL, patience 5 |
| Mixed precision | if CUDA is available |

Train a separate model for each ground-truth mixture condition and training seed. Do not provide `theta` as an input.

### 7.6 Seed policy

Keep these seeds distinct in every run record:

- environment/data seed;
- generator-choice seed;
- model initialization seed;
- minibatch-order seed;
- probe-set seed.

The pilot uses at least three model seeds per mixture. The full result should use five unless compute or time prevents it.

## 8. Primary measurement: counterfactual causal reliance

Predictive accuracy is not the mechanism measure. The primary analysis directly asks how the generator and transformer respond when one causal input changes while the other is held fixed.

### 8.1 Factorial probe prefixes

Build a dedicated probe generator that creates valid sequence prefixes with independently controlled reward and action histories.

The full-feedback design permits this because reward trajectories are generated independently of actions. The probe builder should:

1. Sample reward histories from the same environment as training.
2. Compute their final \(z^Q\).
3. Retain histories near target quantiles, initially \(z^Q\approx -1\) and \(z^Q\approx +1\), with configurable tolerance.
4. Sample natural action-history prefixes from the training generator.
5. Construct matched inputs by combining a fixed action prefix with alternative reward histories, or a fixed reward history with alternative last choices.
6. Confirm that every manipulated value lies within the central support of training inputs.

The primary factorial cells are:

| Reward signal | Previous choice / kernel |
|---|---|
| \(z^Q\approx-1\) | \(K=-1\) |
| \(z^Q\approx-1\) | \(K=+1\) |
| \(z^Q\approx+1\) | \(K=-1\) |
| \(z^Q\approx+1\) | \(K=+1\) |

Use at least 2,000 matched base prefixes for the final estimate. Start with 200 for tests.

### 8.2 Ground-truth effects

For each matched base context, evaluate the generator logit under the two reward interventions and the two kernel interventions.

Define:

\[
C_Q^G
=
\mathbb{E}\left[
\left|\eta(z^Q=+1,K)-\eta(z^Q=-1,K)\right|
\right],
\]

\[
C_K^G
=
\mathbb{E}\left[
\left|\eta(z^Q,K=+1)-\eta(z^Q,K=-1)\right|
\right].
\]

Then define realized ground-truth choice-kernel reliance:

\[
\lambda_G
=
\frac{C_K^G}{C_Q^G+C_K^G}.
\]

For the idealized factorial intervention, these effects should be close to \(2s|\cos\theta|\) and \(2s|\sin\theta|\). Unit tests should verify this.

### 8.3 Transformer effects

Run the same matched prefixes through the trained transformer. Let \(f_\phi(h)\) be the model log-odds for option 1.

Define:

\[
C_Q^M
=
\mathbb{E}\left[
\left|f_\phi(h_{z^Q=+1,K})-f_\phi(h_{z^Q=-1,K})\right|
\right],
\]

\[
C_K^M
=
\mathbb{E}\left[
\left|f_\phi(h_{z^Q,K=+1})-f_\phi(h_{z^Q,K=-1})\right|
\right].
\]

Then:

\[
\lambda_M
=
\frac{C_K^M}{C_Q^M+C_K^M}.
\]

Bootstrap over base prefixes to obtain a 95% confidence interval. Report the effects themselves as well as their ratio; a ratio can conceal a model that is insensitive to both inputs.

### 8.4 Signed effects and interaction

In addition to absolute effects, report signed logit changes. Fit the descriptive factorial model:

\[
f_\phi(h)
=
\gamma_0
+\gamma_Q z^Q
+\gamma_K K
+\gamma_{QK}z^QK
+\epsilon.
\]

This regression is a summary of the probe surface, not the primary causal definition. A large interaction indicates that a one-number mixture estimate is insufficient.

### 8.5 Support diagnostics

Counterfactual evaluations can become misleading if the edited prefixes are far from the model’s training support. The probe report must include:

- target and achieved \(z^Q\) distributions;
- frequency of the four factorial cells in natural held-out data;
- input feature ranges versus training ranges;
- sensitivity to narrower matching tolerances;
- separate results on naturally occurring conflict trials.

Do not discard the counterfactual analysis merely because some combinations are uncommon; instead, quantify the support limitation.

## 9. Conventional analysis estimates

The purpose of these analyses is to test whether common model-analysis approaches recover \(\lambda_M\). They are not substitutes for the counterfactual measure.

### 9.1 Embedding-channel ablation

Implement forward flags:

```python
model(batch, ablate_action=False, ablate_reward=False,
      return_activations=False)
```

When a channel is ablated, zero its embedding contribution after encoding and before it is added to the residual stream. This avoids inventing an unseen categorical mask token.

On held-out natural sessions, calculate:

\[
\Delta\mathrm{NLL}_{A}
=
\mathrm{NLL}(\text{action ablated})-\mathrm{NLL}(\text{intact}),
\]

\[
\Delta\mathrm{NLL}_{R}
=
\mathrm{NLL}(\text{reward ablated})-\mathrm{NLL}(\text{intact}).
\]

Define the ablation-based choice reliance only when the denominator is positive:

\[
\lambda_A^{\mathrm{ablation}}
=
\frac{\Delta\mathrm{NLL}_{A}}
{\Delta\mathrm{NLL}_{A}+\Delta\mathrm{NLL}_{R}}.
\]

Always report the signed raw changes. Do not clip negative effects silently.

### 9.2 Permutation importance

As a robustness analysis:

- permute action histories across sessions while holding reward histories fixed;
- permute reward histories across sessions while holding action histories fixed;
- preserve trial index and session length;
- repeat at least 20 times.

Report NLL increases and variability. This manipulation may disrupt the joint distribution, so label it as importance under permutation, not a pure causal effect.

### 9.3 Hidden-state probes

At every transformer layer, train probes using frozen hidden states to predict:

- continuous \(z^Q_t\): ridge regression, report cross-validated \(R^2\);
- binary \(K_t\): logistic regression, report balanced accuracy and AUROC.

Probe splits must be by session, not by trial. Tune regularization on validation sessions. Compare with:

- shuffled-label controls;
- probes on the raw observable history summarized by simple hand-crafted baselines;
- dimensionality-matched random features if time permits.

Probe success means the variable is decodable. It does not establish that the transformer uses it. Do not convert probe scores into \(\lambda_A\) unless a separate, explicitly justified calibration is added.

### 9.4 Mutual information

Mutual information is optional and secondary. If implemented, estimate conditional predictive information such as:

\[
I(a_t; K_t \mid z^Q_t)
\quad\text{and}\quad
I(a_t; z^Q_t \mid K_t)
\]

for the generator, dataset, and model samples. Use it to characterize information present in a distribution, not to infer causal use or mechanistic identity. Any estimator must be validated on synthetic distributions with known MI before being applied to hidden states.

## 10. Baselines

Implement these before interpreting the transformer:

### 10.1 Oracle generator

Evaluate the true generating policy on held-out data. This provides the irreducible NLL reference.

### 10.2 Correctly specified behavioral regression

Fit logistic regression using the true \(z^Q_t\), \(K_t\), and their interaction. It should recover the generator coefficients within sampling error. Failure means the dataset or fitting code is wrong.

### 10.3 Observable-history logistic baseline

Fit a small model using hand-crafted features computable from observed history:

- exponentially weighted reward difference;
- previous choice;
- optional recent-choice count.

This indicates whether a transformer is necessary for predictive performance and helps interpret shortcut availability.

### 10.4 GRU baseline

Optional after the transformer pilot. A small GRU can test whether any bias is specific to transformer training or shared by flexible sequence models. Do not block Phase 1 on this baseline.

## 11. Primary experimental grid

### 11.1 Fast pilot

Run:

- angles: \(0, \pi/4, \pi/2\);
- three transformer seeds per angle;
- one dataset seed per angle initially;
- default model size;
- 2,000 training sessions during debugging, then 10,000;
- 200 probe bases during debugging, then 2,000.

This produces nine trained models.

### 11.2 Main sweep

Run:

- angles: \(0, \pi/8, \pi/4, 3\pi/8, \pi/2\);
- five transformer seeds per angle;
- at least two independent dataset seeds if time permits;
- default model size.

### 11.3 Capacity and data sweeps

Only after a calibration deviation is observed, vary one factor at a time:

- model size: 2/64/2 heads, 4/128/4 heads, 6/256/8 heads;
- training sessions: 1k, 10k, 100k;
- sequence length: 32, 64, 128;
- overall determinism \(s\): 0.75, 1.5, 3.0.

The purpose is to determine whether bias is caused by data scarcity, capacity, or a persistent learning preference.

## 12. Evaluation metrics

Every run must save:

### Predictive metrics

- test NLL;
- accuracy;
- Brier score;
- expected calibration error;
- NLL gap from oracle;
- per-trial-position NLL.

Accuracy must not be the sole performance metric because high choice determinism can make it insensitive to mechanistic errors.

### Mechanistic metrics

- \(C_Q^G\), \(C_K^G\), and \(\lambda_G\);
- \(C_Q^M\), \(C_K^M\), and \(\lambda_M\);
- signed reward and kernel effects;
- factorial interaction \(\gamma_{QK}\);
- bootstrap confidence intervals;
- mechanistic calibration error \(|\lambda_M-\lambda_G|\).

### Analysis metrics

- \(\Delta\mathrm{NLL}_{A}\) and \(\Delta\mathrm{NLL}_{R}\);
- \(\lambda_A^{\mathrm{ablation}}\), when defined;
- permutation importance;
- layerwise probe performance;
- analysis error \(|\lambda_A-\lambda_M|\) for estimators that define a mixture.

## 13. Required figures

Generate these automatically from saved metrics:

1. **Mechanistic calibration plot**  
   x-axis: \(\lambda_G\); y-axis: \(\lambda_M\); points by seed; mean and 95% interval; identity line.

2. **Performance versus mechanism plot**  
   Test NLL or oracle NLL gap alongside \(|\lambda_M-\lambda_G|\). This tests whether high predictive fit can coexist with mechanistic mismatch.

3. **Generator, model, and analysis comparison**  
   For each mixture, show \(\lambda_G\), \(\lambda_M\), and ablation-based \(\lambda_A\).

4. **Factorial response surface**  
   Model logit across reward-signal and previous-choice conditions, with generator surface for comparison.

5. **Layerwise decodability**  
   Probe performance for \(z^Q\) and \(K\) across layers, shown separately from causal reliance.

6. **Ablation effects**  
   Raw NLL increases for action and reward channel ablations.

All plots must be generated from tidy CSV or JSON outputs, never directly from transient in-memory results.

## 14. Statistical analysis

Treat model seed as a replication unit. Do not treat individual trials as independent replications of a learned mechanism.

Primary descriptive model:

\[
\lambda_M
=
\beta_0+\beta_1\lambda_G+\epsilon.
\]

Mechanistic calibration predicts approximately \(\beta_0=0\) and \(\beta_1=1\). With few mixture conditions, emphasize confidence intervals, calibration plots, and effect sizes rather than a binary significance claim.

Also report:

- mean signed calibration error \(\lambda_M-\lambda_G\);
- maximum absolute calibration error;
- monotonicity of \(\lambda_M\) across mixture conditions;
- seed-to-seed variability;
- whether predictive NLL remains near oracle when calibration error is large.

If multiple dataset seeds are used, fit a hierarchical or mixed-effects analysis with dataset seed and model seed represented separately. This is optional for the first pilot.

## 18. Required tests

Implementation is not complete until all tests pass.

### 18.1 Generator tests

- With \(\theta=0\), generator logits are invariant to the previous choice.
- With \(\theta=\pi/2\), generator logits are invariant to reward history.
- With \(\alpha=0\), \(Q\) remains constant.
- Reward outcomes are independent of the selected action conditional on environment state.
- Fixed seeds reproduce bit-identical sessions.
- Reversal hazard produces the expected empirical rate within tolerance.

### 18.2 Oracle recovery tests

- Logistic regression on true \(z^Q\) and \(K\) recovers coefficients from a large generated dataset.
- Counterfactual code returns analytic generator effects for the extreme and mixed conditions.
- Computed \(\lambda_G\) is monotonic in \(\theta\).

### 18.3 Alignment and leakage tests

- Model input at position \(t\) contains only data through \(t-1\).
- Changing any future action or reward leaves all earlier logits unchanged.
- Changing reward at trial \(t\) may affect prediction at \(t+1\), not prediction at \(t\).
- Dataset targets align with the intended positions.

### 18.4 Model tests

- Forward shapes are correct on CPU and CUDA when available.
- Channel-ablation flags zero only the intended embedding contribution.
- Activation-return mode does not change logits.
- The model can overfit a tiny fixed batch.
- A short training run beats an empirical-frequency baseline.

### 18.5 Probe tests

- Each matched reward pair shares the same action prefix.
- Each matched kernel pair shares the same reward history and earlier action history.
- Achieved \(z^Q\) values meet the configured tolerance.
- The four factorial cells are balanced.
- Bootstrap output is deterministic under a fixed seed.

### 18.6 Split tests

- Session IDs are unique.
- No ID or environment trajectory is shared across splits.
- Probe histories are not copied from training sessions.

## 20. Pilot go/no-go criteria

### 20.1 Immediate technical no-go conditions

Stop and fix the framework if:

- the oracle regression cannot recover generator coefficients;
- generator counterfactual effects disagree with analytic values;
- future information leaks into model predictions;
- the transformer cannot beat simple baselines;
- factorial probes fall outside configured support or cannot be balanced;
- results are not reproducible under fixed seeds.

These are implementation failures, not scientific findings.

### 20.2 Scientific go conditions

Proceed to the main sweep if at least one of the following occurs:

1. \(\lambda_M\) systematically deviates from \(\lambda_G\) while model NLL remains close to the oracle.
2. \(\lambda_M\) changes nonlinearly, abruptly, or non-monotonically as \(\lambda_G\) changes.
3. A stable preference for reward or choice history appears across seeds.
4. Standard ablation or probe conclusions disagree with the counterfactual model mechanism.
5. Calibration is good in the easy benchmark but degrades under a clearly specified change in data, capacity, or signal correlation.

### 20.3 Informative null result

If the transformer tracks the true mixture well, do not immediately abandon the project. The clean result establishes a calibrated baseline. The next manipulations should make the inference problem harder in a controlled order:

1. reduce dataset size;
2. correlate reward and choice signals more strongly;
3. introduce unequal temporal complexity;
4. switch to a decaying choice kernel;
5. move to partial feedback;
6. vary architecture and optimization;
7. only then consider pretrained-model SFT or Centaur.

The question becomes where mechanistic calibration breaks, rather than whether it always fails.

## 21. Anticipated interpretations

### Pattern A: accurate prediction and calibrated mechanism

The transformer’s reliance tracks the generator. This supports using the benchmark as a validated measurement framework and motivates harder conditions.

### Pattern B: accurate prediction and biased mechanism

This is the central phenomenon of interest. It shows that predictive adequacy does not guarantee recovery of the data-generating mixture.

### Pattern C: biased model mechanism, correctly recovered by analysis

The interpretability method works at the model level, but the model cannot be treated as a transparent estimator of the data mechanism.

### Pattern D: calibrated model mechanism, misleading conventional analysis

The learning process is faithful, but the analysis method mischaracterizes it.

### Pattern E: both model and analysis are biased

The pipeline compounds two inference gaps. Report them separately.

### Pattern F: low predictive performance

No mechanistic conclusion is warranted. Fix the task, capacity, data volume, or optimization first.

## 22. Claims the project may and may not support

### Supported, if demonstrated

- A transformer can achieve high predictive performance while relying on a mechanism mixture different from the known generator.
- A learned model mechanism need not equal the data-generating mechanism.
- Conventional model analysis may or may not recover the transformer’s actual causal reliance.
- Mechanistic calibration can be measured using controlled synthetic interventions.

### Not supported by Phase 1 alone

- Humans use only reward dependence or only choice dependence.
- Centaur necessarily uses the same mechanism as the small transformer.
- A decoded variable is causally used.
- An ablated channel constitutes the complete generative mechanism.
- All transformers prefer the same shortcut.
- A model-derived structure is a scientific discovery about the domain without independent validation.

Use “model mechanism,” “data-generating mechanism,” and “analysis estimate” consistently.
